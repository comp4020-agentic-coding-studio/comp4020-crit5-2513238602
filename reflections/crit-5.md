# Crit 5 reflection

The breakthrough was treating the drawn line as a promise to the player, not merely as a physics object. My first complete version technically recognised a closed loop and could resolve collisions, but during the first desktop playtest the loop fell under gravity and collapsed into a flat rope. The state-machine tests were green, yet the game felt wrong because the visible result no longer matched the gesture. Adding shape-preserving constraints and a soft return force kept the line recognisably theirs while retaining enough movement for bee impacts to feel physical. That change turned a functioning prototype into an understandable game.

This work changed what I want to be as a software developer by making me value two kinds of evidence at the same time. Pure rule tests protected the round contract: collision loses, five seconds wins, stars reflect ink, and level six ends the game. But only playing the real pointer loop at both desktop and phone sizes revealed whether the interaction was legible and satisfying. I want to build systems where automated checks create confidence without pretending to replace human perception. I also want to become more disciplined about subtraction. A worried dog, a hive, a moving visual hint, and immediate consequences taught the mechanic more effectively than a modal or paragraph could have. The best implementation was not the one with the most explanation; it was the one whose behaviour made explanation unnecessary.
